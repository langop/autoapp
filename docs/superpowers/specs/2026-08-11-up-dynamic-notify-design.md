# UP 动态跟踪桌面提醒 — 设计文档

**日期：** 2026-08-11  
**状态：** 待实现  
**关联：** Bili UP Viewer（Electron）

## 目标

应用运行期间，对用户勾选「提醒」的已收藏 UP，定时检查是否有新动态，并通过 Windows 桌面通知提醒。点击通知可进入该 UP 动态页。

## 非目标

- 应用完全退出后的后台检查 / 开机自启 / 系统托盘常驻
- 与收藏完全独立的第二套跟踪列表
- 评论更新提醒、直播开播提醒

## 已确认决策

| 项 | 决策 |
|---|---|
| 跟踪范围 | 已收藏 UP 中单独勾选「提醒」 |
| 运行条件 | 仅应用进程在运行时检查 |
| 默认间隔 | 约 15 分钟（设置可改） |
| 实现位置 | 主进程定时轮询 + Electron `Notification` |
| 置顶动态 | 比较时忽略置顶，避免误报 |

## 数据

### 收藏项扩展（`favorites.json`）

在现有字段上增加：

- `notifyEnabled: boolean`（默认 `false`）

### 跟踪游标（`userData/watch.json`）

```json
{
  "byUid": {
    "123": { "lastDynamicId": "xxx", "updatedAt": 0 }
  }
}
```

首次为某 UP 开启提醒或首次检查到动态时：只写入当前最新非置顶动态 id，**不弹通知**。

### 设置扩展（`settings.json`）

- `notifyEnabled: boolean`（总开关，默认 `true`）
- `notifyIntervalMin: number`（分钟，默认 `15`，建议范围 5–60）

## 界面

- 收藏卡片：增加「提醒」开关；点击开关不触发进入动态
- 设置页：动态提醒总开关 + 检查间隔（分钟）
- 无独立「跟踪列表」页

## 检查逻辑（主进程）

1. 应用 `ready` 后启动定时器；间隔取自设置（默认 15 分钟）
2. 若总开关关闭，跳过本轮
3. 取出 `notifyEnabled === true` 的收藏，**串行**请求每人动态首页（复用现有 `fetchDynamics` / client 队列）
4. 从返回列表取第一条 **非置顶** 动态 id  
   - 若全是置顶或没有动态：本轮跳过该 UP
5. 与 `watch.json` 比较：
   - 无记录：写入当前 id，不通知
   - id 变化：发桌面通知，再更新游标
6. 网络 / 风控错误：该 UP 本轮跳过，保留旧游标，不弹错误通知

设置变更（间隔 / 总开关）后：重启定时器使新配置生效。

## 通知行为

- 标题：`{UP名} 更新了动态`
- 正文：动态标题或正文摘要（截断）
- 点击通知：聚焦主窗口，打开该 UP 动态（复用现有直达动态流程）
- 需在 Windows 上申请/使用通知权限（Electron `Notification.isSupported()`；不支持则静默跳过）

## 错误与边界

- Cookie / 风控导致拉动态失败：本轮跳过，下次再试
- 用户取消收藏：清除对应 `watch` 游标，并停止检查
- 关闭提醒开关：保留游标，但不再检查；再次开启时若 id 未变不弹，若期间有更新则按「有变化」通知（可接受）
- 多 UP 同一轮都有更新：可连续弹多条通知（每 UP 一条）

## 测试要点

- `notifyEnabled` 读写与默认值
- 游标：首次只记不弹；id 变化才弹
- 忽略置顶动态参与比较
- 间隔/总开关变更后定时器行为（可用短间隔单测或注入时钟）

## 验收

1. 收藏里打开「提醒」后，约一个间隔内若有新动态，出现 Windows 通知  
2. 首次开启不误报历史动态  
3. 点击通知进入对应 UP 动态  
4. 关闭总开关或退出应用后不再检查
